## 零、结论摘要：三层各有一个卡点

**第一层（逻辑，最致命）**：论文的核心主张是「无差异」，但全项目**没有任何等价性检验**——在 `scripts/` 与 `src/` 中检索 `tost|equivalence|effect_size|cohen|cliff`，命中数为 0。p > 0.05 只能说明「未检出差异」，不能说明「差异小于实际意义阈值」。这是当前稿子最大的逻辑漏洞，也是审稿人最容易一击致命的地方。

**第二层（机制）**：把阴性结果升级为机制发现的**关键反向实验尚未进行**。我们已经证明「专家高度相关 → 权重熵 0.99998 → 增益为零」，但没有做反向验证：如果刻意让专家去相关，门控是否恢复增益？没有这个实验，「门控无效」可以被解释为「你的专家不够多样」或「你没调好」，而不是结构性结论。

**第三层（公平性）**：被检验机制的门控超参数是硬编码的（`LogisticRegression(C=1.0, class_weight="balanced", max_iter=400)`、交叉拟合折数 `cv=5`、专家数 `Q=4`），而随机森林、极端随机树与 XGBoost 都做了 5×3 嵌套交叉验证调参。**被检验方法没调参、对照方法调了参**，这个不对称足以让审稿人否定「机制无效」这一结论。必须补一门控的超参搜索，或明确论证其超参不敏感。

**审计期间的附带修复**：仓库原先缺少 `pytest.ini`，导致打包目录 `_release_stage_v3b_20260912` 中复制的整套测试被重复收集，`pytest` 报 49 个 import mismatch 错误。补齐配置后 **118 项测试全部通过**。这是打包污染代码树的实例，也说明仓库卫生需要治理（见第七节）。

## 十一、三条补齐路线

**路线 A：最小可发表（约 6–8 天）**

只做 P0。产出是一篇诚实的「阴性结果 + 机制边界」论文，可投中等 SCI 或优质期刊。风险：数据规模与基线覆盖仍会被追问，可能需要一轮大修。

**路线 B：稳健版本（约 2–3 周，推荐）**

P0 + P1。补齐时间协议、全语料规模、代价敏感、资源画像与统计功效。此时论文的每一层都有对应的证据，审稿人难以从方法层面否定。这是投入产出比最高的路线。

**路线 C：冲高版本（约 5–8 周）**

P0 + P1 + P2，并把「专家多样性与增益的关系」提升为全文核心贡献，配以第四个数据集与深度基线。风险是计算量大、周期长，且阴性/弱效应结论在本数据集上仍可能不变。

## 十三、一句话总结

当前研究在**数据审计与可复现性**上已经超出多数同类论文，但在**统计推断（等价性）、机制消融（去相关与多样性）、基线覆盖（神经基线）与方法公平性（门控调参）**四点上存在硬缺口。其中等价性检验与门控调参是两条「不补就过不了审」的线；专家多样性与增益的剂量—反应分析是最值得做的一项，因为它能把这篇论文从阴性结果升级为机制结论。
