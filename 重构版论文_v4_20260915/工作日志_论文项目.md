## 八、每轮标准操作流程（本全流程固定执行）

1. **起点核对**：`git status --short` 确认工作区干净；跑闸门确认起点全绿，若已失败则本轮只做修复。
2. **选一项**：按轮转清单取一项（跨文档数字 / 图注 / 统计重算 / 中英对齐 / 补充材料索引 / 参考文献 / 测试覆盖 / 措辞体例 / 数据来源 / 交付件一致性），一轮只推进一项。
3. **只修有证据的缺陷**：数字或结论与产物不符时，先写脚本断言源值，再改写稿件；不手改 Markdown，不留无出处的数字。
4. **重建产物**：`build_restructured_manuscript_v4.py --only all` → `convert_equations_word_v41.py` → `build_publication_manifest.py` → `export_manuscript_tables_v1.py` / `export_submission_text_v1.py` → `package_submission_bundle_v18.py`。
5. **过闸门**：45 项检查全绿才提交；不绿则回退本轮改动并报告。
6. **发布**：`git add` → commit（Round NN 小步提交）→ 刷新 tag → push 主干与标签 → 同步桌面交付目录。
7. **汇报**：只在「本轮提交了修复」或「发现需用户决定的问题」时汇报，其余轮次保持安静。
